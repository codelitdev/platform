# Origin-product implementation inventory

Status: accepted for Phase 0 extraction planning.

This inventory names the canonical source for each concern the Platform
kernel, observability package, MCP kit, and reference product will extract
or re-implement. Origin-product canaries consume **published** packed
artifacts; workspace-link proof is not a substitute.

Tenant nouns stay product-owned: FrontLit/SendLit `team`, MediaLit
`apikey`/media-library tenancy, CourseLit `domain`/`school`.

## FrontLit — origin canary for admin auth, BFF, invitations, REST/MCP shape

| Concern          | Canonical source                                                                                                   | Notes                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| Auth             | `frontlit/apps/api/src/auth/better-auth.ts`, `resolve-auth.ts`, `middleware.ts`                                    | Better Auth + `@codelitdev/oauth-server-kit` (`resolveBetterAuthSession`, OAuth pages). Session cookies, OAuth bearer, API keys.       |
| REST             | `frontlit/packages/api-contract/src/contract.ts`, `frontlit/apps/api/src/**/routes.ts`                             | ts-rest + Zod; OpenAPI from the contract. Thin route adapters over application queries.                                                |
| MCP              | `frontlit/apps/api/src/mcp/`, `auth/better-auth-mcp.test.ts`, `auth/middleware.ts` (`createAuthMiddleware("mcp")`) | Streamable HTTP MCP. OAuth bearer and API key; not browser sessions. Resource metadata at `/.well-known/oauth-protected-resource/mcp`. |
| Tenancy          | `frontlit/apps/api/src/auth/require-team.ts`, `oauth-team-selection.ts`                                            | Tenant noun is `team`. Membership revalidated per request. OAuth team selection uses public team IDs (`team_…`).                       |
| Invitations      | `frontlit/packages/api-contract/src/schemas/memberships.ts`, `frontlit/apps/web/app/team-invitations/`             | Application-owned invitations with secret in fragment; digest stored server-side.                                                      |
| IDs              | FrontLit architecture §IDs; `publicIdCheck` usage across `apps/api`                                                | Internal UUIDv7 `id` (never exposed) + prefixed public IDs (`pg_…`, `blog_…`, `team_…`, `tinv_…`).                                     |
| API keys         | `frontlit/apps/api/src/auth/resolve-auth.ts` (`getApiKeyBySecret`)                                                 | Tenant-bound keys. Secrets must not appear in response bodies (middleware tests).                                                      |
| Telemetry        | product wrappers around request logging in `apps/api`                                                              | Not the observability extraction baseline; SendLit API and CourseLit Queue are.                                                        |
| Worker lifecycle | FrontLit embedding/outbox workers under `apps/api`                                                                 | Product-owned jobs; not the shared worker-observability source.                                                                        |
| Tests            | `frontlit/apps/api/src/test/db.ts`, `auth/*.test.ts`                                                               | PGlite-backed authz and membership tests; `publicIdCheck` and FK cascades exercised.                                                   |
| Deployment       | `frontlit/docker-compose.yml`, `frontlit/.github`                                                                  | Docker Compose PostgreSQL; product CI.                                                                                                 |

**Auth mechanisms actually used:** Better Auth session, OAuth bearer, team API key.

**Origin canary for:** kernel auth/tenant conventions, invitation flow shape, REST/MCP adapter split.
