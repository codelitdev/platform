# ADR 0016: Stateless MCP on protocol 2026-07-28

Status: accepted  
Date: 2026-10-30

## Context

`@codelitdev/mcp-server-kit` was built on the MCP TypeScript SDK 1, which
supports protocol revisions up to `2025-11-25`. It kept an in-memory session
map keyed by `Mcp-Session-Id`, served `GET` and `DELETE` for sessions, and
reshaped SDK results: it prepended a `{ type: "json" }` content item, which
MCP does not define, and turned tool failures into JSON-RPC errors with
string codes, which JSON-RPC does not allow.

ChatGPT rejected every CourseLit tool result because of the `json` item and
retried the call, so each "failed" `products.create` created a product.

MCP `2026-07-28` removes protocol sessions and the `initialize` handshake,
adds `server/discover`, requires `Mcp-Method`/`Mcp-Name` headers, `resultType`
on results, and cache hints on list results. SendLit already serves it with
SDK 2, and SendLit, FrontLit, and MediaLit are to move onto this kit.

## Decision

- The kit runs on SDK 2 (`@modelcontextprotocol/server`) and serves every
  request through `createMcpHandler` with a fresh request-local server. The
  SDK implements the protocol; the kit does not translate envelopes or
  classify protocol eras itself.
- 2025-era Streamable HTTP clients are served by the SDK's stateless legacy
  mode (`legacy: "stateless"`). No `Mcp-Session-Id` is minted, and `GET` and
  `DELETE` answer `405`.
- The kit keeps its record-based `handle()` so products route MCP like any
  other request. A legacy reply arrives as a one-response SSE stream, and the
  kit returns that response as `application/json`, which Streamable HTTP
  allows.
- Results are not reshaped. A tool result is `structuredContent` plus one
  `text` copy. A tool failure is a tool result with `isError: true` and
  `structuredContent: { code, message, details }`, so the model sees the
  stable platform code. Failures before dispatch (authentication, context
  resolution, shutdown) return the platform error body with its HTTP status.
- Product tool schemas stay Zod 3. The kit converts them to JSON Schema once
  per process and advertises them without `$schema`, under MCP's default
  dialect.
- `tools/list` and `server/discover` carry a five-minute, private cache hint
  by default.

## Consequences

- Any API instance can serve any MCP request; there is no session state to
  lose on restart or to pin to an instance.
- Clients that relied on `Mcp-Session-Id` or a `GET` stream must work
  statelessly. Current clients (Claude, ChatGPT, VS Code, Inspector) do.
- Products that read tool failures from JSON-RPC `error.code` must read
  `result.structuredContent.code` when `result.isError` is set.
- The kit no longer exports session or SDK 1 transport helpers.
- Multi round-trip requests, `subscriptions/listen` change notifications,
  and tasks are not exposed. Kit tools are request/response only.
